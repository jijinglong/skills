# 角色设计与一致性

先让不同角色能分清，再让同一个角色跨视图、跨服装和状态保持身份。统一画风不等于统一脸。提示词与参考图都不能保证零漂移，必须查看实际输出后才能判定。

## 入口与范围

读取用户最新要求、现有角色／造型设定与必要剧本片段；已有可靠资料就继续，不重问已明确的问题。用户只要设定或提示词时完成文本；明确要求生成时才调用图像工具。授权生成与替换已包含在任务中时按授权范围做完，不反复征求同意。

按阶段读取参考，不一次加载全部：

- 撞脸、建立身份、换装、左右连续性：[身份设计与连续性](references/design-and-continuity.md)。
- 编写提示词、检查尺寸和版式；同批包含道具：[固定版式与提示词](references/layout-and-prompts.md)。
- 实际出图、视觉复核、批量执行、入库：[生产与验收](references/production-and-review.md)。
- 想知道整合了什么、为何没照搬外部默认值：[来源与取舍](references/sources.md)。

## 角色设计流程

1. **分清身份与造型。** 群体如工匠、摊贩、宾客、护卫拆为甲／乙／丙等独立人物；同人换衣、烟熏、受伤、一个月后属于造型状态，不另造身份。保留已有故事事实，不借重设计改年龄、亲缘、职业或结局。
2. **先做全角色差异表。** 每人写审美定位、3个主要识别锚点、脸部结构和身形。主角在明确美感基础上拉开差异，普通配角自然可信，剧情明确要求的丑角保留特点；不能把区别等同于脸更长、颧颌更硬或五官更极端，也不按正反派机械决定美丑。先横向比较容易混淆的人物。新设计标为提案，已接受的身份除非用户要求重设计，否则保持。
3. **建立各自母版。** 写一条完整母版提示词，每张只含一个人、一个造型的五个视图。用户要求重做身份时，从新设计建立母版，不拿撞脸旧图锁住新脸。旧图只控制明确保留的服装或标记，不混进其他角色的身份。
4. **用母版派生造型。** 同一人每套造型都回到同一张已认可或按当前授权完成复核的身份母版；不要用上一套换装连续派生下一套，不拿多张矛盾面孔平均。母版约束脸和骨架，当期文字约束服装、发式盘法、污损与伤态。
5. **分别验收美感、差异与一致性。** 母版先看是否符合角色审美定位、年龄和健康肤质，再对不同角色做中性脸并排比较、同人做母版与变体比较。衣服做旧不等于皮肤做旧。文本检查通过只代表可生成；母版被用户否决时停用该母版及依赖造型，先修正方向再继续批量。

## 固定交付约定

- **角色和道具均为16:9横图，目标2560×1440。** 与项目／成片比例解耦。优先使用内置生图；当前已接受其原始尺寸，工具不支持精确像素时如实记录，不能假装输出达标或自行改用付费提供商。详见版式参考中的尺寸能力分支。
- **左宽2/3，右宽1/3；右侧上下各1/2。** 角色左区为正／严格侧／背全身，右上正脸、右下三分之四侧脸；只有一套服装。道具右侧为两个点名细节，不能替换成人脸或不同开合状态。
- **仅两条1像素纯白不透明实线。** 竖线在宽2/3处贯穿全高，横线在高1/2处只跨右区；左区不加列间线。无表情网格、色卡、标签、卡片间隔或外框。
- **重新生成指完整新图。** 引用身份母版生成新设定板与贴脸、局部补丁不同；当前约定不贴脸、不拼接独立视图、不补画分割线、不缩放或补边冒充原生输出。用户另有明确编辑请求时按新请求处理。

## 最小交付

按请求范围保存：角色差异表、每人身份契约、对应母版／变体完整提示词；生成后增加真实文件路径、宽高、参考来源和验收结果。沿用项目已有目录和格式，不复制一套平行管理系统。

维护“待生成／待复核／可用／失败”的真实状态；用户没要求生产就到文本交付为止。保存小型清单与缩略预览，原图留在磁盘／素材库，避免在对话里积累完整图片或base64。检查PNG真实尺寸可用只读脚本：

```bash
python3 scripts/inspect-sheet.py /absolute/path/to/image.png
```

该脚本只报告文件事实，不能判定人脸、布局或1像素分割线通过。
