# 产品展示卡片设计

把卡片当作小型产品封面设计：先确定要让人看见的内容，再精选素材、组织构图，最后在真实页面尺寸下校准。质感来自主体、比例、内容与空间关系，不能只靠更大的底色、圆角和阴影。

## 先确定展示任务

读现有页面与用户参考，明确卡片所在区域、实际宽高、要表达的产品价值和点击行为。参考主要用来分析标题位置、视觉占比、裁切、前后关系和留白，不照搬其品牌、图片或整页。

已有方向时直接推进；只询问会改变内容或构图的缺失信息。把一次项目的深色、斜放纸片或人物题材当作可选表达，不固化成所有卡片的样式。

## 精选内容，再选画法

优先查看用户提供的素材、项目现有资源与授权可读的数据，核对图片真实尺寸和内容。只有素材描述或尺寸、没有文件时，不能声称已经使用原素材；使用替代示意应明确说明。选择一个主角和少量有解释作用的辅助元素；选图考虑题材、色彩、清晰度和彼此关系，而不是用所有可用素材填满容器。

| 内容条件                         | 适合的表达                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------- |
| 有角色、服装、场景等独立素材     | 主体大图配辅助视图，形成素材画板或空间组合                                                        |
| 价值在技能、代码、文档或工具结果 | 抽取真实内容，用 HTML/CSS 放大重排为文档、终端或结果面板                                          |
| 需要证明真实界面                 | 选择代表性局部，保持界面结构；整页截图只在完整界面本身是展示对象时使用                            |
| 原图较小或素材不足               | 采用文字/原生界面主导、小图辅助；有图像生成工具时按需补充背景或概念视觉，并区分生成示意与真实功能 |

真实名称、摘要、命令和仓库来自可核对的内容。没有数据时省略统计、评分和状态，不编造。未经公开授权，不把项目私有素材打包进可分发技能或模板。

## 先写构图，再写代码

用几句话确定：**主角是什么、占多大、放哪里；辅助元素为什么存在；文字和入口留在哪里；小屏如何重排。** 必要时画小草图。

- 卡片边界负责入口与整体轮廓；内部元素各自有叙事作用。去掉“截图外再包一层巨大空背景”的机械套盒。
- 标题与一句说明保持独立可读；视觉元素聚集在一个主要区域，标题区留出呼吸空间。
- 一个主体承担视觉重量，辅助元素在尺寸、位置或明暗上退后。重叠不能挡住人脸、关键结果、技能名或重要命令。
- 用来自素材的色彩和少量接触阴影建立层次。透视、旋转、模糊和渐变只在构图需要时使用；系列卡片统一标题基线、边距与入口位置，各卡仍应体现自己的产品内容。

需要具体起点时，按内容选择 [构图示例](references/composition-recipes.md)，不要原样套用整套视觉。

## 用代码组织可维护的视觉

遵守目标项目的组件、样式和目录约定，在页面专属组合层实现，复用现有基础组件。图片保留为独立素材，标题、说明、代码和界面文字尽量原生渲染；不要为容易排版的 UI 生成一张带文字的大图。

分开组织项目数据、可访问入口与装饰性主视觉。容器内管理定位和层级，超出部分按构图裁切；不要用全局高 z-index 影响导航。固定尺寸展示可局部采用绝对定位，文字内容仍需有可预期的空间。

整卡可点击时使用一个真实链接，不在其中嵌套假按钮、复制控件或第二个交互。确有复制等次要操作时，改用非交互容器，主链接与真实按钮同级，各自保留焦点与操作反馈。装饰图用空 alt；有独立信息的组合提供准确替代说明，避免重复朗读全部装饰文字。保留焦点反馈，非必要不加入持续漂浮动画，交互运动遵循 reduced motion。

## 在实际卡片里校准

先看桌面截图，再看实际小屏视口。不要把整张桌面设计等比例缩成手机缩略图：优先保留主角与关键文字，减少辅助内容或调整位置。长代码应换行或采用与展示目的相符的排版；装饰性展示不引入为了看清而必须操作的滚动区。

逐项查看实际画面：

- 第一眼能辨认产品价值和主角，图片没有不必要的放大模糊，文字与背景有足够对比。
- 人脸、标题、命令没有意外裁切；重叠关系明确，阴影和边框没有抢走主体。
- 桌面与手机均无页面横向溢出，卡片之间对齐，悬停和聚焦不越过外层页面层级。
- 链接去向与打开方式正确，图片加载成功；按项目要求运行检查。

先修正最明显的构图问题，再调整装饰。交付实现、清晰的预览截图，以及必要的素材来源记录；若环境或任务约束无法运行浏览器，说明静态检查范围和未验证的视觉部分，不把格式或构建通过称作视觉效果已获认可。
