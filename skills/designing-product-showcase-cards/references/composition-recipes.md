# 按内容选择构图

这些是可变的空间关系，不是固定皮肤。先匹配产品价值，再从项目品牌和素材取色。没有要求时，不默认给每张卡片加斜角、纸张或深色背景。

## 素材画板：一个主体，两个补充视角

适合角色、服装、设计素材和创作工具。先选相互关联的素材，如同一角色的肖像和全身设定；辅助场景负责说明用途，不与主角争夺注意力。

```text
┌────────────────────────────┐
│ 标题                       │
│ 一句价值说明               │
│                            │
│       ┌──────────┐ ┌─────┐ │
│       │  主肖像  │ │全身 │ │
│       │          │ │设定 │ │
│  ┌────────┐      │ │     │ │
│  │辅助场景│──────┘ └─────┘ │
│  └────────┘             → │
└────────────────────────────┘
```

以宽约560、高约520的卡片为例：标题区约占上方四分之一；主肖像宽约40–45%，全身图约28–32%，场景约25–33%。这是起点，按图片比例调整。肖像优先保住脸部，全身优先使用能完整展示服装的比例；不要为了填满空隙裁掉脚部或关键配件。

照片自身有完整背景时，可以用清晰的素材板边界组织；已抠图时，可用底座、背景和接触阴影构成同一空间。不要随意混用不同光线和视角造成廉价拼贴。

小屏可缩小或移除辅助场景，保留主肖像与全身之间的联系；重新检查宽高关系，不只调整整体 scale。

## 内容面板：让技能、代码与结果成为主角

适合开发工具、技能库、文档和知识产品。提取一个真实内容单元，放大到正常浏览距离可识别的尺寸。

例如，技能目录使用：

- 一页文档：文件类型、真实技能名、短摘要和来源。
- 一个前景终端：真实安装命令，按 shell 语法断行，不能为美观改坏参数或 URL。
- 如需表达系列，背景可露出少量内容板边缘；不要虚构条目、状态或数量。

文档与终端可以通过浅深对比形成层次，也可以用同色不同材质表达。先保证技能名和命令读得清，再决定是否旋转。被遮住的区域保留为留白，避免半行文字、半枚图标露在重叠边缘。

小屏优先去掉重复的元信息，保留技能名与关键命令；命令过长可拆成合法的多行。字号不应随整体缩放而失去可读性。

## 真实界面：局部成为画面，截图充当证据

用户明确要求原网站截图或忠实还原时，保留实际界面，不替换成虚构面板。允许取局部时，选择能体现核心任务的区域，以适度边界或阴影整合到卡片；用户要求原图完整或不加装饰时，直接遵守。不要先缩小整页，再用大背景填满剩余空间。

必须展示完整界面时，让外层标题说明价值，并接受其中正文不是阅读对象；不要为了让小字可读而重新伪造 UI。移动端可选择另一真实视口，但应保持产品身份和关键内容一致。

## 常见误差与修正顺序

| 看到的问题             | 先修正什么                                   |
| ---------------------- | -------------------------------------------- |
| 看起来像网页缩略图     | 重新选择内容单元与主体尺寸，再调整边框       |
| 素材很多但没有重点     | 删辅助元素，让一个主体承担视觉重量           |
| 画面仍然空而散         | 调整元素间距离和视觉聚集区，不直接把背景撑大 |
| 有层次但显得杂乱       | 统一光线、透视和材质，减少旋转方向           |
| 桌面好看、小屏像缩略图 | 重新安排位置与内容数量，保持关键文字尺寸     |
| 边缘有半行字或残留图标 | 移开、缩短或删去被遮挡内容，不靠蒙层掩盖     |
