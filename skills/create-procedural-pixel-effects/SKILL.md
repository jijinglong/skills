# 用代码制作像素特效

在低分辨率像素网格上用代码画帧。按目标播放尺寸评估轮廓、运动和节奏。特效源码、真实预览和最终素材要对应同一组参数。整支短片的镜头、剪辑和配乐由当前项目的视频流程处理。

## 先确定交付和可复用素材

- 确认主体、发生位置或锚点、可用画幅、循环或一次性、是否包含角色及受击目标。按用户的用途决定交付源码、实时效果、透明图集或视频预览。
- 优先查项目里已有的同类效果和参数。颜色、强度、方向或密度变化优先试已有参数。需要改变形状、运动或演出时间轴时，从最接近的实现派生新变体。
- 使用 PixelFX 时读 [PixelFX 工具和导出](references/pixelfx.md)。Beat 的下载包包含源码 ZIP、普通特效索引和另存的角色演出。需要改参数或重渲染时，从现有 checkout 或项目下载包取得源码，在可写工作目录运行。已有项目引擎能满足要求时，沿用它的渲染和导出入口。

## 设计帧和动作

| 需求 | 实现方式 |
| --- | --- |
| 篝火、水波、光环等稳定循环 | 用周期相位计算每帧。噪声、漂移、粒子出生和消退都要跨周期接续。 |
| 爆炸、碰撞、弹跳和烟尘 | 用固定或有上限的时间步更新粒子。把出现、峰值和消散写成可调节的时间段，给尾部留出清空的时间。 |
| 角色冲刺、施法或击中 | 把特效和动作关键姿势分别编写，共用释放与命中时间。先画预备姿势，再对齐武器或手与特效锚点，检查命中停顿、目标反应和收势。 |

- 用整数像素对齐关键轮廓，预览放大时使用最近邻和整数倍缩放。用小范围色阶建立体积与材料感。发光和基础颜色分层处理，避免光效盖掉主体或在边界出现方框。
- 用固定随机种子复现粒子。放大看像素边缘，再按实际观看尺寸看轮廓与运动。

## 渲染、观看、修正

1. 先做一次成本低的可播放预览。造型方向有取舍时再做少量差异明确的变体，例如窄长剑弧与厚短剑弧。
2. 实际打开帧图并播放动画。循环至少观察一次跨周期的过渡。一次性特效检查启动、峰值和尾迹。带角色的版本检查剪影、手或武器与特效相交的那一帧，以及停顿和恢复。
3. 按能定位的问题修改，例如缩短最亮的三帧、减小光晕半径、把命中移到刀尖接触时刻。用相同参数重渲染，确认变更出现在成品里。

## 交付检查

- 透明图集和帧数据放在一起，核对 JSON 的图片引用、帧数、矩形边界、时长、顺序和锚点。把图放到实际背景或代表性的浅、深底上检查透明边缘与光晕。发光层合入透明 PNG 后的亮度可能随背景变化。
- 需要带角色时，确认打开的是演出导出。检查命中停顿已出现在实际帧序列里。游戏运行时是否也要暂停由接入逻辑决定。
- 有目标工程或导入器时，用其正常入口回放。记录源码版本、特效 ID、色板、种子、帧率和输出位置，方便复现。Beat 按作品目录约定归档单作品素材，跨作品复用的素材再放 `assets/`。
