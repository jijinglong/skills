# Spark 同步与复核

使用项目当前的 Spark 文档、界面或已生成的 API 客户端核对权限、工作区、契约和模型能力。有 API 时，先读当前 OpenAPI 和项目状态，再通过受支持的接口写入。已有项目按稳定的项目 ID 或作品标识复用。创建项目和任务使用契约支持的幂等键；更新现有剧本或设定时使用最新版本号，冲突后回读和合并本次授权范围内的改动。

## 同步顺序

| 本地内容 | Spark 内容 | 核对 |
| --- | --- | --- |
| 作品入口、剧本与原语文本 | 项目与剧本 | 作品身份、场次和场景编号、动作、台词或歌词保留完整 |
| 人物设定和采用的造型图 | 角色及其造型 | 同一个角色、对应场景的造型和图片均可打开 |
| 地点及其采用的场景图 | 场景及其视图 | 剧本引用相符；多角度图片归属正确 |
| 图像与裁剪好的音频 | 项目媒体 | 实际媒体类型、时长、状态就绪、上传及请求限制 |
| 剧本的镜头、生成方案与计时 | 分镜、提示词和参考绑定 | 镜头及生成段对应、引用和顺序正确、实际编译结果一致 |

按依赖关系分批写入。先建立项目和正文，再让定义引用就绪媒体，让分镜引用真实的定义和媒体。接口将镜头参考与提示词引用分开保存时，两处都要核对，例如当前契约的 `references` 与 `videoMentions`。正文中的 `@` 名称应能解析到对应图片或音频。状态未就绪时先查上传、转码或处理结果。对照模型能力选择仅首帧、图像参考或可接收音频的模式，并核对生成时长、计划剪辑时长、比例及分辨率能否分别设置。

较大的高清 PNG 即使逐张合规，也可能超过模型接口的组合请求限制。若接口把附件放进 JSON 的 Base64 字符串，预计每个文件会占约 `4 × ceil(字节数 / 3)` 字节，另计 JSON 和请求的其他字段。按真实上传方式计算。需要压缩时保留原始生成图，提供肉眼检查过的 JPEG 或目标尺寸适配版供该次调用。

## 音频驱动与对白编译

- 演唱任务把原语歌词保留在剧本，并按节奏写入分镜提示词。把目标音频绑定为驱动或参考，具体取决于模型支持的输入方式。核对编译后的提示词，排除重复配音和额外的语言指令。
- 若当前 Spark 编译器把分镜的结构化对白自动拼成普通话口播指令，而任务由原语歌曲驱动，在该生成分镜中留空专供口播使用的对白字段。保留剧本中的歌词和分镜中的演唱说明，并确认音频附件已绑定。若最终正文仍附带与演唱矛盾的无配乐或发声限制，改用支持这段音频的生成模式或独立对口型工具。普通对白场景继续使用结构化对白，核对说话人、口语和音色。
- 连续音轨可以配多次画面切换。准备一条视频时，核对各镜头时间都相对于该视频和该段音频；分段时，分别核对局部时码与原曲时码，生成时长留出的余量在剪辑时按实际发声裁去。

## 回读与交付

通过项目页面或读取接口确认剧本、定义、分镜、时间、参考顺序、媒体和模型配置。查看实际编译出的提示词或可用的提交预览，特别核对音频的职责与语言。记录项目入口、同步范围、采用版本及待补项。同步结果和生成任务进度分别回读；媒体尚未生成时报告项目配置的完成程度。
