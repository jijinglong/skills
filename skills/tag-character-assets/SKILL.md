# 角色素材标注

为角色素材生成可追溯、可校验的筛选标签。只标当前资料支持的内容，不靠职业、性别、年龄或画风刻板印象补满字段。

## 先定位标准和任务范围

- 从用户给出的项目与资源位置开始，读取适用的项目说明。先找项目的标签判定标准、字段字典及实际校验代码；如存在 `docs/character-tagging-standard.md`、`docs/character-filter-taxonomy.md` 和 `packages/contracts/src/character-attributes.ts`，分别读取判定依据、存储约定和当前枚举。不存在这些路径时搜索同职责文件，或使用用户本次提供的标准，不假定项目绝对路径。
- 项目的当前字典决定字段 ID、枚举和顺序，判定标准决定含义。两者不一致时指出具体差异，不自行增加枚举、修改界面或重标全部存量资源。
- 确定资源 ID、实际参考图和来源信息，区分新入库、补缺、指定字段重标。没有要求写库时交付候选标注；已有明确入库／回填授权则完成该范围，不重复要求批准。创建本技能本身不授权标注或改写现库。

## 看图并按字段取证

1. 建立资源与参考图的稳定映射。批量可用联系图初筛，按需打开对应原图检查发尾、躯干、材质或不同视角。不把多个角色、不同版本的证据混用。
2. 每项资源至少读取实际图片或明确提供的可靠画面描述。资料未提供的内容不声称已查看；文字观察、人设与亲眼观察分开注明。
3. 按项目字段逐项判断，保留证据位置。形态和国籍不能靠外貌猜；中性不能替代性别未知。气质区分视觉呈现与明确的虚构人设，不对真实人物推断心理疾病、真实性格或道德。
4. 高置信、有直接依据且无冲突的值进入候选属性；边界或冲突值进入待核。使用高／中／低判断等级，不编造百分比，不为了完整率赋予默认值。
5. 按项目允许的组合处理发型、题材与气质。尤其检查专业干练与街头酷飒、冷淡高冷与忧郁暗黑人设、Q版与幼年、科幻与未来、近代与民国、光头与遮盖。定义和边界从当前项目标准读取，不仅查同义词。

## 产出、校验与交付

- 按 [输出约定](references/output-format.md) 生成标签、逐标签证据、待核项和字典未覆盖项。真实资源 ID、图片或描述引用必须可回查；每个选中值都有依据，不以整条记录一个笼统理由代替。
- 从项目当前字典导出一份 catalog 快照；将判断标准要求的单值上限加入对应字段。标准或用户允许例外时先调整 catalog，不把个人默认当数据库限制。对开放值如国家，`values` 使用 `null`，不能拿现库仅有的国家当永久白名单。
- 执行 `python3 <本技能目录>/scripts/validate_annotations.py <labels.json> --catalog <catalog.json>`。此脚本只读文件，校验结构、枚举、字段基数、证据覆盖和待核候选；不会判断图片或执行入库。还要复核图文依据、互斥标签和资源对应关系，不能把结构通过当语义正确。
- 先以覆盖来源、风格与不确定情况的小批资源验证一致性，再按用户范围处理剩余批次。已有标准与一致性验证足够时不用每批重新设计。
- 有写入授权时走项目现有导入／更新通道。候选属性与证据、置信、待核项分开保存；只更新指定范围。未知不清空已有值，已有人工结论不因来源弱标签被覆盖，重标保留差异及依据。写入后回读核对。
- 汇报处理数量、已标与待核情况、可查看的标注清单和实际写入结果。不要只说“已按规则完成”。
